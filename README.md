# 创作引擎：游戏设计 MVP

一个完全本地、规则驱动、不使用 AI 的游戏创作引擎网页应用。它不再把游戏设计当成一份必须依次填完的表格，而是持续帮助创作者澄清核心、补齐结构、做好判断，并把最大未知变成下一项可验证工作。

## 当前工作流

1. **澄清核心：** 保留作者原话，提炼不可失去的火花、玩家 Fantasy、核心动作、目标、约束、核心玩法句和体验承诺。
2. **建立设计骨架：** 定义项目专属支柱、原子玩家循环、关键选择、形式元素、设计→动态→体验因果链，以及叙事/机制/美学/技术四类设计维度。
3. **判断与取舍：** 明确目标玩家、规则预期、参考、差异化、硬约束和六个可行性分面，选出最大风险并记录当前决定与反证条件。
4. **形成行动路径：** 汇总未决问题，选择一号问题，写出可验证假设、最小原型、测试与停止条件，并拆成有产物和完成定义的工作任务。
5. **证据与迭代：** 区分事实和解释，对照支持/反驳信号，决定保留、调整、替换或继续取样，再把影响回流到相关设计节点。

每个关键节点都可以“已决定、暂作假设、不适用或延期”结束，不会强迫用户编造答案。左侧“设计路径”支持非线性跳转，右侧“当前设计状态”同时显示主干完成度、高风险未知项、待复核决定和下一号问题。

旧版 `v2` 六步项目会在首次打开时迁移到 `v3`，原始答案保留；叙事/机制/美学/技术会迁移为通用设计维度，而不会被误当成项目专属支柱。

## 本地与隐私

- 运行时不调用 AI、模型或任何网络 API。
- 项目数据自动保存在当前浏览器的 `localStorage` 中。
- 旧版项目会在首次打开时迁移到新版数据结构。
- “重新开始”会在确认后清除当前浏览器中的项目数据。

## 本地运行

需要 Node.js 22.13 或更高版本。

```bash
npm install
npm run dev
```

默认开发地址为 `http://localhost:3000/`。

## 验证

```bash
npm run lint
npm test
```

`npm test` 会先完成生产构建，再检查服务端首屏和本地工作流契约。
